# Сборка приложения записи (macOS) — пошагово

Инструкция для владельца, а не для программиста. Все команды набираются в
**Терминале** (Программы → Утилиты → Терминал) — их можно копировать целиком
и вставлять, потом Enter.

Собирать надо на **Mac**. Собранное приложение потом переносится на любой
другой Mac обычным копированием.

---

## Шаг 0. Проверьте сервер

До сборки в системе должно быть готово две вещи, иначе приложению нечего будет
показывать.

1. **Переменная `APP_KEY` на сервере.** Coolify → ваш ресурс → Environment
   Variables. Если строки `APP_KEY` там нет — добавьте её.
   Значение сгенерируйте так (в Терминале):

   ```
   python3 -c "import secrets; print(secrets.token_urlsafe(32))"
   ```

   Скопируйте результат, вставьте в Coolify как значение `APP_KEY`, нажмите
   **Redeploy**. Это же значение понадобится на Шаге 4 — сохраните его.

2. **Хотя бы одна точка продажи.** Откройте админку → раздел **«Точки
   продажи»** → добавьте студии. Их приложение и покажет в списке.

---

## Шаг 1. Один раз поставить три инструмента

Если вы уже собирали приложение раньше — пропустите шаг.

**1.1. Инструменты разработчика Apple.** В Терминале:

```
xcode-select --install
```

Откроется окно — нажмите «Установить» и дождитесь конца. Если ответит
«command line tools are already installed» — значит уже стоят, идём дальше.

**1.2. Node.js.** Откройте https://nodejs.org и скачайте версию **LTS** для
macOS. Запустите скачанный `.pkg` и пройдите установку кнопкой «Продолжить».

**1.3. Rust.** В Терминале:

```
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

Спросит вариант установки — нажмите **1** и Enter. После установки **закройте
Терминал и откройте заново** (иначе он не увидит новую программу).

Затем добавьте обе архитектуры Mac — чтобы приложение работало и на новых
маках, и на старых Intel:

```
rustup target add aarch64-apple-darwin x86_64-apple-darwin
```

**Проверка.** Три команды должны напечатать номера версий, а не «command not
found»:

```
node -v
cargo --version
xcodebuild -version
```

## Шаг 2. Скачать код

Если у вас настроен доступ к репозиторию по git:

```
cd ~/Downloads
git clone https://github.com/borinsobaka-lab/audio-analitics.git
cd audio-analitics
git checkout claude/audio-recording-sales-analysis-x6tit4
```

Если git не настроен — откройте репозиторий на GitHub в браузере, переключите
ветку на `claude/audio-recording-sales-analysis-x6tit4`, нажмите зелёную
кнопку **Code → Download ZIP**, распакуйте в «Загрузки». Папка будет
называться `audio-analitics-claude-audio-recording-sales-analysis-x6tit4` —
в командах ниже подставляйте это имя вместо `audio-analitics`.

**Если код уже скачан раньше** — обновите его:

```
cd ~/Downloads/audio-analitics
git checkout claude/audio-recording-sales-analysis-x6tit4
git pull
```

## Шаг 4. Вписать адрес сервера и создать ключ подписи

Оба пункта делаются один раз и остаются на этом маке.

**4.1. Адрес сервера и ключ приложения.** Это то самое «что куда вставлять».

```
cp src-tauri/build.env.example src-tauri/build.env
open -e src-tauri/build.env
```

Откроется TextEdit с двумя строками. Замените значения на свои:

```
AA_SERVER_URL=https://api-audio.вашдомен
AA_APP_KEY=сюда_значение_APP_KEY_из_Coolify
```

- **AA_SERVER_URL** — адрес сервера. Это тот же адрес, по которому в браузере
  открывается страница `/health` и пишет `{"status":"ok"}`. Без слэша в конце.
- **AA_APP_KEY** — ровно то значение, что стоит в Coolify в переменной
  `APP_KEY`. Скопируйте оттуда целиком, без кавычек и пробелов.

Сохраните (⌘S) и закройте окно.

> Файл `build.env` в репозиторий не попадает — в нём лежит ключ.
>
> Если этот шаг пропустить, приложение всё равно соберётся: тогда адрес и ключ
> вводятся один раз внутри приложения, в свёрнутом разделе **«Для
> настройщика»**. Но лучше вписать здесь — тогда у сотрудника на ресепшене
> вообще не будет полей, в которых можно ошибиться.

**4.2. Ключ подписи обновлений.** Тем же ключом будут подписываться все
будущие обновления; приложение проверяет подпись своим вшитым публичным
ключом и не установит ничего чужого.

```
npm install
npm run keygen
```

На вопрос про пароль нажмите Enter два раза. Ключ ляжет в
`src-tauri/updater.key` — **сделайте его копию в менеджере паролей.**
Потеряете ключ — установленные приложения перестанут принимать обновления, и
их придётся переставлять на каждой студии руками.

## Шаг 5. Собрать

```
npm run build:mac:universal
```

Это долго: **10–25 минут в первый раз** (компилируется
всё целиком). Дальше сборки идут за пару минут. Терминал в это время будет
сыпать строчками — так и должно быть, ждите.

Готово, когда в конце появится:

```
Архитектуры бандла:
x86_64 arm64

✅ Готово. Версия 0.2.0.

Чтобы студии обновились сами, выложите в админке (раздел «Приложение»)
эти два файла:
   …/Audio Recorder.app.tar.gz
   …/Audio Recorder.app.tar.gz.sig
```

Строчка `x86_64 arm64` означает, что приложение пойдёт и на новых маках, и на
Intel. Два файла в конце — это обновление; что с ними делать, в Шаге 8.

## Шаг 6. Установить

Готовое приложение лежит здесь:

```
desktop/src-tauri/target/universal-apple-darwin/release/bundle/macos/Audio Recorder.app
```

Открыть эту папку в Finder:

```
open src-tauri/target/universal-apple-darwin/release/bundle/macos
```

Перетащите **Audio Recorder.app** в «Программы». Затем обязательно выполните
в Терминале:

```
xattr -cr "/Applications/Audio Recorder.app"
```

Без этой строки macOS скажет, что приложение «повреждено»: подпись у нас
своя, а не купленная у Apple. Команда снимает карантин, делается один раз.

Рядом лежит и `.dmg` (папка `bundle/dmg`) — им удобно переносить приложение
на другие маки: скопировать файл, открыть, перетащить в «Программы», и там
тоже выполнить `xattr -cr`.

## Шаг 7. Первый запуск

1. Откройте **Audio Recorder** из «Программ».
2. macOS спросит доступ к микрофону — **Разрешить**. Если окно не появилось:
   Системные настройки → Конфиденциальность и безопасность → Микрофон →
   включить Audio Recorder.
3. Раскройте **«Настройки»** → выберите свою студию в списке **«Точка
   продажи»** → **«Сохранить настройки»**.
4. Проверьте верхний блок на главном экране — там написано, какая студия и
   какой микрофон выбраны. Если микрофон не тот (например, наушники вместо
   микрофона стойки), поменяйте его в Системные настройки → Звук → Вход и
   перезапустите приложение.
5. Галочка **«Запускать вместе с компьютером»** уже включена — приложение
   будет открываться само после включения мака.

Всё. Сотруднику остаётся выбирать себя в списке «Кто работает сегодня» и
нажимать «Начать рабочий день».

## Шаг 8. Как выкатывать обновления дальше

Первую установку делают руками, один раз на студию (шаги 6–7). **Дальше
студии обновляются сами** — обходить их больше не нужно.

Порядок такой:

```
cd ~/Downloads/audio-analitics
git pull
cd desktop
npm run bump
npm run build:mac:universal
```

`npm run bump` поднимает номер версии на единицу. Это обязательно: приложения
сравнивают свою версию с серверной и обновляются, только если серверная
больше. Со старым номером сервер сборку просто не примет.

Дальше откройте админку → раздел **«Приложение»** → «Выложить новую версию»:

1. **Архив сборки** — файл `Audio Recorder.app.tar.gz`, путь к нему напечатан
   в конце сборки.
2. **Подпись** — он же с `.sig` на конце, лежит рядом.
3. **Что изменилось** — одна строка, её увидят на ресепшене.

Нажмите «Выложить» и подождите минуту-две — архив весит десятки мегабайт.

Всё. На каждом компьютере в приложении появится синяя плашка «Вышла новая
версия», сотрудник нажмёт «Обновить и перезапустить», и через полминуты у него
свежая версия. Приложение проверяет обновления при запуске и раз в час; если
хочется сразу — в его настройках есть «Проверить обновления».

Во время смены кнопка обновления заблокирована: перезапуск оборвал бы запись.
Обновятся утром или после «Завершить день».

Если версия оказалась неудачной — в админке у неё есть кнопка **«Снять»**:
раздача прекращается, у кого не успел обновиться — не обновятся.

## Если что-то пошло не так

| Что видно | Что делать |
|---|---|
| `command not found: npm` / `cargo` | Не выполнен Шаг 1 либо не перезапущен Терминал после установки Rust |
| В списке точек «Список недоступен» | Проверьте `AA_SERVER_URL` (открывается ли `/health` в браузере) и что `APP_KEY` на сервере совпадает с `AA_APP_KEY` |
| «Точки не заведены» | Заведите студии в админке, раздел «Точки продажи» |
| «Приложение повреждено» при запуске | Не выполнена команда `xattr -cr` из Шага 6 |
| В списке менеджеров пусто | Заведите сотрудников в админке и убедитесь, что они привязаны к этой студии |
| Сборка ругается на `universal-apple-darwin` | Не выполнена команда `rustup target add …` из Шага 1.3 |
| В конце сборки «⚠️ updater.key не найден» | Не выполнен Шаг 1.4 (`npm run keygen`) — сборка есть, обновления не будет |
| Админка: «Версия 0.2.0 уже выложена» | Забыли `npm run bump` перед сборкой |
| В приложении не появляется плашка обновления | Версия на сервере не выше установленной; либо `APP_KEY` в приложении и на сервере разные |

---

## Что не надо делать повторно

`build.env` и `updater.key` остаются на месте между сборками — адрес, ключ
приложения и ключ подписи заново вводить не нужно. Инструменты из Шага 1
ставятся один раз.
