# Сборка приложения записи (macOS) — пошагово

Инструкция для владельца, а не для программиста. Все команды набираются в
**Терминале** (Программы → Утилиты → Терминал) — их можно копировать целиком
и вставлять, потом Enter.

Собирать надо на **Mac**. Собранное приложение потом переносится на любой
другой Mac обычным копированием.

---

## Шаг 0. Проверьте сервер

До сборки в системе должно быть готово две вещи, иначе приложению нечего будет
показывать.

1. **Переменная `APP_KEY` на сервере.** Coolify → ваш ресурс → Environment
   Variables. Если строки `APP_KEY` там нет — добавьте её.
   Значение сгенерируйте так (в Терминале):

   ```
   python3 -c "import secrets; print(secrets.token_urlsafe(32))"
   ```

   Скопируйте результат, вставьте в Coolify как значение `APP_KEY`, нажмите
   **Redeploy**. Это же значение понадобится на Шаге 4 — сохраните его.

2. **Хотя бы одна точка продажи.** Откройте админку → раздел **«Точки
   продажи»** → добавьте студии. Их приложение и покажет в списке.

## Шаг 1. Один раз поставить три инструмента

Если вы уже собирали приложение раньше — пропустите шаг.

**1.1. Инструменты разработчика Apple.** В Терминале:

```
xcode-select --install
```

Откроется окно — нажмите «Установить» и дождитесь конца. Если ответит
«command line tools are already installed» — значит уже стоят, идём дальше.

**1.2. Node.js.** Откройте https://nodejs.org и скачайте версию **LTS** для
macOS. Запустите скачанный `.pkg` и пройдите установку кнопкой «Продолжить».

**1.3. Rust.** В Терминале:

```
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

Спросит вариант установки — нажмите **1** и Enter. После установки **закройте
Терминал и откройте заново** (иначе он не увидит новую программу).

Затем добавьте обе архитектуры Mac — чтобы приложение работало и на новых
маках, и на старых Intel:

```
rustup target add aarch64-apple-darwin x86_64-apple-darwin
```

**Проверка.** Три команды должны напечатать номера версий, а не «command not
found»:

```
node -v
cargo --version
xcodebuild -version
```

## Шаг 4. Вписать адрес сервера и ключ

Это то самое «что куда вставлять». Делается один раз и остаётся в файле.

```
cp src-tauri/build.env.example src-tauri/build.env
open -e src-tauri/build.env
```

Откроется TextEdit с двумя строками. Замените значения на свои:

```
AA_SERVER_URL=https://api-audio.вашдомен
AA_APP_KEY=сюда_значение_APP_KEY_из_Coolify
```

- **AA_SERVER_URL** — адрес сервера. Это тот же адрес, по которому в браузере
  открывается страница `/health` и пишет `{"status":"ok"}`. Без слэша в конце.
- **AA_APP_KEY** — ровно то значение, что стоит в Coolify в переменной
  `APP_KEY`. Скопируйте оттуда целиком, без кавычек и пробелов.

Сохраните (⌘S) и закройте окно.

> Файл `build.env` в репозиторий не попадает — в нём лежит ключ.
>
> Если этот шаг пропустить, приложение всё равно соберётся: тогда адрес и ключ
> вводятся один раз внутри приложения, в свёрнутом разделе **«Для
> настройщика»**. Но лучше вписать здесь — тогда у сотрудника на ресепшене
> вообще не будет полей, в которых можно ошибиться.

## Шаг 4.5. Создать ключ обновлений — один раз навсегда

Этот шаг делается **ровно один раз**, на том маке, где вы собираете. Он даёт
приложению возможность обновляться по кнопке, без обхода студий.

```
npm install
npm run keygen
```

Спросит пароль для ключа — нажмите **Enter два раза** (задать и подтвердить,
оба раза пусто). Пароль тут только мешает: его пришлось бы подставлять при
каждой сборке, а файл ключа и так лежит на одном вашем маке.

Появятся два файла и одна правка:

- `src-tauri/updater.key` — **приватный** ключ. Им подписывается каждая новая
  сборка. В репозиторий он не попадает и остаётся только на вашем маке.
- `src-tauri/updater.key.pub` — публичный.
- Публичный ключ автоматически вписывается в `src-tauri/tauri.conf.json` и
  вшивается в приложение.

> **Сделайте копию `updater.key` в менеджере паролей прямо сейчас.**
> Публичный ключ вшит в те приложения, которые вы поставите в студиях, и они
> принимают обновления **только** с подписью этим приватным ключом. Потеряете
> файл — обновление по кнопке умрёт: новый ключ старые приложения не примут, и
> придётся обойти студии с флешкой ещё раз.
>
> В подписи ключом обновлений весь смысл защиты: даже если кто-то подменит
> ответ нашего сервера, приложение не установит чужой код — подпись не сойдётся.

Строку с публичным ключом в `tauri.conf.json` нужно закоммитить, если работаете
через git. Приватный ключ — **никогда**.

## Шаг 5. Собрать

Две команды подряд:

```
npm install
npm run build:mac:universal
```

Первая быстрая, вторая долгая: **10–25 минут в первый раз** (компилируется
всё целиком). Дальше сборки идут за пару минут. Терминал в это время будет
сыпать строчками — так и должно быть, ждите.

Готово, когда в конце появится:

```
Info.plist обновлён, приложение переподписано:
...
Архитектуры бандла:
x86_64 arm64
...
✅ Готово. Версия 0.3.0.
```

Строчка `x86_64 arm64` означает, что приложение пойдёт и на новых маках, и на
Intel.

Сборка кладёт рядом три вещи:

| Файл | Зачем |
|---|---|
| `Audio Recorder.app` | само приложение — им ставят на новый компьютер (Шаг 6) |
| `Audio Recorder.app.tar.gz` | архив обновления — его выкладывают в админку |
| `Audio Recorder.app.tar.gz.sig` | подпись к архиву — выкладывается вместе с ним |

Первый раз нужен только `.app`: в студиях ещё нечего обновлять. Начиная со
второй сборки хватит двух последних файлов — см. «Обновление приложения потом».

## Шаг 6. Забрать сборку на флешку

> Этот шаг и следующий нужны **только для первой установки** на компьютер —
> и один раз для тех компьютеров, где сейчас стоит старая сборка без
> обновлений. Дальше приложение обновляется по кнопке, см. последний раздел.

Готовое приложение лежит здесь:

```
desktop/src-tauri/target/universal-apple-darwin/release/bundle/macos/Audio Recorder.app
```

Открыть эту папку в Finder:

```
open src-tauri/target/universal-apple-darwin/release/bundle/macos
```

Флешка почти наверняка отформатирована в exFAT (заводской формат, понятный и
Windows), а exFAT не хранит признак «этот файл — программа» и символические
ссылки. Приложение, скопированное на такую флешку и обратно, на другом маке
не запустится. Поэтому кладём его **архивом** — так формат флешки не важен:

```
cd src-tauri/target/universal-apple-darwin/release/bundle/macos
ditto -c -k --sequesterRsrc --keepParent "Audio Recorder.app" ~/Desktop/AudioRecorder.zip
```

`ditto` — не то же самое, что «Сжать» из контекстного меню: он сохраняет
права, ссылки и подпись целиком. Готовый `AudioRecorder.zip` с рабочего стола
перетащите на флешку.

> **`.dmg` из папки `bundle/dmg` брать нельзя.** Tauri собирает его до того,
> как мы дописываем в приложение разрешение на микрофон и переподписываем
> бандл, — внутри лежит версия, которая будет писать тишину.

Если флешка отформатирована в **APFS** или **Mac OS Extended**, архив не
нужен: можно перетащить сам `.app`.

Если копируете **на ту же машину**, где собирали, флешка не нужна — просто
перетащите `.app` в «Программы» и переходите к Шагу 7.

## Шаг 6.1. Поставить на компьютер студии

На маке ресепшена:

1. Вставьте флешку. Скопируйте `AudioRecorder.zip` **на рабочий стол** (не
   распаковывайте прямо на флешке), дважды щёлкните по нему — рядом появится
   `Audio Recorder.app`. Перетащите его в папку **«Программы»**.
2. Откройте Терминал (Программы → Утилиты → Терминал) и выполните:

   ```
   xattr -cr "/Applications/Audio Recorder.app"
   ```

   **Эту строку пропускать нельзя.** Без неё macOS скажет, что приложение
   «повреждено и не может быть открыто»: подпись у нас своя, а не купленная у
   Apple. Команда снимает карантин, делается один раз на компьютер.

3. Там же, следом, переподпишите приложение и проверьте подпись:

   ```
   codesign --force --deep --sign - "/Applications/Audio Recorder.app"
   codesign --verify --verbose "/Applications/Audio Recorder.app"
   ```

   Вторая команда должна ответить `valid on disk`.

   **Порядок важен: сначала `xattr -cr`, потом `codesign`.** Подпись бандла
   запечатывает в том числе расширенные атрибуты файлов внутри него, а
   `xattr -cr` их срезает — и печать перестаёт сходиться. Со сломанной печатью
   macOS не понимает, кто просит микрофон, и отказывает **молча**: окно с
   вопросом не появляется вообще, а приложение пишет тишину. Снаружи это
   выглядит как сломанный микрофон и ищется полдня.

4. Запустите приложение из «Программ».

## Шаг 7. Настроить на месте

1. macOS спросит доступ к микрофону — **Разрешить**. Если окно не появилось:
   Системные настройки → Конфиденциальность и безопасность → Микрофон →
   включить Audio Recorder.
2. Раскройте **«Настройки»** → выберите студию в списке **«Точка продажи»** →
   **«Сохранить настройки»**. Больше в настройки заходить не придётся.
3. Проверьте верхний блок на главном экране — там написано, какая студия и
   какой микрофон выбраны. Если микрофон не тот (например, наушники или
   встроенный вместо микрофона стойки), поменяйте его в Системные настройки →
   Звук → **Вход** и перезапустите приложение.
4. Галочка **«Запускать вместе с компьютером»** уже включена — приложение
   будет открываться само после включения мака. Проверьте, что она стоит.
5. В «Системные настройки → Экономия энергии» снимите засыпание: приложение
   не даёт маку заснуть во время записи, но если он уснёт до её начала, смену
   некому будет запустить.

## Шаг 7.1. Проверить, что записи доезжают — прямо на месте

Не уходите из студии, не сделав это. Проверка занимает пять минут и ловит всё,
что может пойти не так.

1. Выберите себя (или любого менеджера) в списке **«Кто работает сегодня»** и
   нажмите **«Начать рабочий день»**.
2. Скажите вслух несколько фраз у стойки — так, как говорят с клиенткой.
   Смотрите на полосу **«Уровень сигнала»**: она должна шевелиться. Если она
   стоит на нуле и через десять секунд появляется жёлтое предупреждение —
   микрофон не даёт звука, разбирайтесь с ним, а не с приложением.
3. Подождите **6 минут** — приложение режет запись на пятиминутные куски, и
   первый должен успеть уйти на сервер. Под кнопками появится «Загружено на
   сервер: 1».
4. Нажмите **«Завершить день и отправить»** (два раза — второе нажатие
   подтверждает). Дождитесь надписи «День завершён».
5. Откройте админку → раздел **«Смены»**. Там должна появиться сегодняшняя
   смена с именем менеджера и статусом **«Ждёт разбора»**. Нажмите
   **«Обработать»** — через несколько минут статус сменится на «Готово», и
   смену можно открыть и послушать. (Разбор не запускается сам: платить за
   тестовые записи и неудачные дубли незачем.)

Если смена появилась и открылась — всё работает, можно уходить. Эту тестовую
смену потом удалите из админки кнопкой «Удалить».

Дальше сотруднику остаётся только выбирать себя в списке и нажимать «Начать
рабочий день».

## Если что-то пошло не так

| Что видно | Что делать |
|---|---|
| `command not found: npm` / `cargo` | Не выполнен Шаг 1 либо не перезапущен Терминал после установки Rust |
| В списке точек «Список недоступен» | Проверьте `AA_SERVER_URL` (открывается ли `/health` в браузере) и что `APP_KEY` на сервере совпадает с `AA_APP_KEY` |
| «Точки не заведены» | Заведите студии в админке, раздел «Точки продажи» |
| «Приложение повреждено» при запуске | Не выполнена команда `xattr -cr` из Шага 6 |
| В списке менеджеров пусто | Заведите сотрудников в админке, раздел «Сотрудники». К студии они не привязаны — в приложении видны все |
| Уровень сигнала стоит на нуле | Не выдан доступ к микрофону, либо в «Звук → Вход» выбран не тот микрофон |
| Окно с запросом доступа к микрофону не появляется | Сломана подпись: `codesign --force --deep --sign - "/Applications/Audio Recorder.app"`, затем `tccutil reset Microphone ge.stretching.audiorecorder` и перезапуск |
| После пересборки микрофон снова «не даёт сигнала» | Подпись меняется при каждой сборке, и старое разрешение к ней не относится: `tccutil reset Microphone ge.stretching.audiorecorder`, перезапустить, выдать заново |
| Смена не появилась в админке | Дождитесь минуты после «Завершить день»; если пусто — проверьте, что в приложении выбрана та же студия, что смотрите в админке |
| Сборка ругается на `universal-apple-darwin` | Не выполнена команда `rustup target add …` из Шага 1.3 |

## Обновление приложения потом — без поездок в студию

Сборка, которую вы поставили по этой инструкции, умеет обновляться сама. Дальше
всё делается из-за стола, за три шага.

**1. Собрать новую версию (на вашем маке):**

```
cd ~/Downloads/audio-analitics
git pull
cd desktop
npm install
npm run bump
npm run build:mac:universal
```

`npm run bump` поднимает номер версии (0.3.0 → 0.3.1). **Без него сборку не
примут:** приложения обновляются, только если на сервере лежит номер выше их
собственного, а сервер откажется принять версию, которая уже выложена. Для
заметных изменений: `npm run bump -- minor` (0.3.1 → 0.4.0).

`build.env` и ключ обновлений остаются на месте — адрес, ключ и подпись
заново заводить не нужно.

**2. Выложить в админку:**

Откройте админку → раздел **«Приложение»** → «Выложить новую версию». Нужны два
файла из папки сборки:

```
open src-tauri/target/universal-apple-darwin/release/bundle/macos
```

- `Audio Recorder.app.tar.gz` — в поле «Архив сборки»
- `Audio Recorder.app.tar.gz.sig` — в поле «Подпись»

В поле «Что изменилось» напишите одну фразу по-человечески: её увидят на
ресепшене. Номер версии вводить не нужно — он читается из самой сборки.

**3. Ничего.** На ресепшенах в течение часа появится синяя плашка «Вышла новая
версия» с кнопкой **«Обновить и перезапустить»**. Сотрудник нажимает — и через
минуту работает новая версия. Кто хочет не ждать час: «Настройки» → «Проверить
обновления».

Во время смены кнопка заблокирована и подписана «Обновим после завершения
смены»: перезапуск оборвал бы запись.

### Что увидит сотрудник после обновления

Зелёную плашку «Приложение обновлено» с просьбой сказать что-нибудь и
посмотреть на полосу микрофона. Это не формальность: macOS привязывает
разрешение на микрофон к подписи приложения, а у самодельной подписи она
меняется с каждой сборкой. Система вправе счесть обновлённое приложение новым и
спросить доступ заново — если вопрос появится, нужно нажать «Разрешить». Если
полоса стоит на нуле и вопроса не было: Системные настройки →
Конфиденциальность и безопасность → Микрофон → включить Audio Recorder.

Стоит позвонить в студию после первого такого обновления и попросить
посмотреть на полосу — дальше это войдёт в привычку.

### Если что-то пошло не так с обновлением

| Что видно | Что делать |
|---|---|
| Админка: «Версия N уже выложена» | Не выполнен `npm run bump` — поднимите версию и соберите заново |
| Админка: «Нет подписи» | Не приложен файл `.sig`; он лежит рядом с архивом в той же папке |
| Сборка: «Не прописан публичный ключ обновлений» | Не выполнен Шаг 4.5 (`npm run keygen`) |
| Сборка: `incorrect updater private key password` | У ключа задан пароль. Собирайте так: `TAURI_SIGNING_PRIVATE_KEY_PASSWORD='пароль' npm run build:mac:universal`. Пока сборка не стоит ни в одной студии, проще пересоздать ключ без пароля: `rm src-tauri/updater.key src-tauri/updater.key.pub && npm run keygen`, на вопрос про пароль — Enter |
| В приложении плашка не появляется | Проверьте, что версия в админке выше установленной (она видна в «Настройках» приложения), и нажмите «Проверить обновления» |
| «Не удалось установить обновление» | Приложение должно лежать в «Программах», а у пользователя мака должны быть права администратора |
| Старая сборка без обновлений | Приложения, поставленные **до** этой инструкции, кнопку не покажут: у них нет плагина обновлений. Их нужно один раз заменить руками — дальше они обновляются сами |

### Если нужно откатить версию

В разделе «Приложение» нажмите **«Снять»** у плохой сборки — она перестанет
раздаваться, и приложения увидят предыдущую. Скачать её обратно они сами не
смогут: обновление идёт только вверх, вниз — руками с флешкой.
