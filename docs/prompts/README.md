# Промпты метрик

Готовые тексты для админки: **Метрики и анализ → Добавить метрику**.
В каждом файле копируется текст **после разделителя `---`** — от «Ты оцениваешь…»
до конца.

| Файл | Название метрики | Что оценивает | Шкала |
|---|---|---|---|
| `meeting_goal_discovery.md` | Встреча и выявление цели | Первый контакт с **новой** клиенткой до пробного занятия: знакомство, опыт, цель прихода, рассказ о студии, передача тренеру (шаги 1–3 скрипта) | 10 |
| `sale_quality_studio.md` | Качество продажи абонемента | Разговор с ней же после пробного занятия: ощущения, презентация абонементов, закрытие, возражения, следующий шаг (шаги 4–7 скрипта) | 10 |
| `trial_call_quality.md` | Качество звонка (запись на пробное) | Исходящий звонок по заявке/сертификату: представление, квалификация, рекомендация направления, запись с подтверждением, WhatsApp, возражения. Оценивается только по репликам администратора — клиентку в телефонной записи не слышно | 10 |

Обе метрики работают только по сценарию **новой клиентки на пробном занятии**.
Постоянные клиентки, продления и сервисные вопросы отсекаются на этапе
применимости: с постоянной клиенткой достаточно поздороваться, и короткое
приветствие в её адрес — это нормальная работа, а не проваленная встреча.
Поэтому за смену метрики срабатывают всего несколько раз — по числу пробных
занятий, а не по числу разговоров на ресепшене.

Обе метрики заведены в `backend/cli/seed.py` и создаются автоматически при
`python -m cli.seed` для новой организации. Для уже развёрнутой базы добавляйте
их через админку.

## Почему две метрики, а не одна

Встреча и продажа разделены самим занятием — между ними около часа, поэтому в
записи это всегда два разных разговора. Одна общая метрика на оба этапа давала
бы среднее по несопоставимым фрагментам: «встреча без продажи» выглядела бы как
проваленная продажа. Раздельные метрики дают два независимых показателя дня —
насколько хорошо администратор выясняет цель и насколько хорошо закрывает, —
и калибруются тоже независимо.

Каждая метрика явно отказывается оценивать чужую зону: если фрагмент содержит
только знакомство, метрика продажи вернёт «не применима», и наоборот.

## Как калибровать

1. Прогнать реальный день, открыть отчёт.
2. Прослушать 2–3 разговора и сравнить свою оценку с оценкой ИИ.
3. Систематическое расхождение правится точечно:
   - **завышает** — добавить ограничитель («…→ не выше N») или ужесточить якорь;
   - **занижает** — смягчить формулировку соответствующего пункта чек-листа;
   - **срабатывает не там** — уточнить раздел «КОГДА МЕТРИКА ПРИМЕНИМА».
4. Нажать «Обработать заново» на том же дне — пересчёт идёт по той же записи,
   поэтому видно именно эффект правки промпта.

Менять всё сразу не стоит: одна правка за прогон, иначе непонятно, что подействовало.
